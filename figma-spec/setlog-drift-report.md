## F2. 코드 ↔ PRD 값 드리프트 — 어느 쪽이 의도인지 결정 필요

QA를 통과해 현재 화면에 보이는 건 코드 값이다. Figma 스펙 v2는 **화면과의 얼라인을 위해 코드 값을 기준**으로 하고 ⚠ 표기했다. PRD를 코드 값으로 갱신할지, 코드를 PRD 값으로 재생성할지는 항목별 제품 판단.

## F3. 권고 처리 방향

```
F1 (내부 드리프트 10건)  → PRD v3.42 "버그: 문서 정합성" 일괄 수정. 코드 변경 없음 (문서만 코드에 맞춤)
F2 중 #22 (v3.19 표기)   → 명백한 버그. 다음 재생성 시 수정 (버전 문자열을 PRD 버전과 동기화하는 규칙 추가 권고)
F2 중 #21 (인라인 PRIMITIVE) → ⚙️-A 체크리스트가 이미 금지 — 다음 재생성 시 코드 수정 + 검증 스크립트를 파일 전체로 확대
F2 중 #19·20 (하드코딩 rgba) → dim35 활용 여부 결정 + 검증 스크립트에 색상 문자열 검사 추가
F2 나머지 (시각 값 8건)  → 항목별로 "화면에 보이는 현재 값 유지(PRD 갱신)" vs "PRD 값으로 되돌림(코드 재생성)" 결정 필요.
                           현재 화면이 QA 승인된 상태이므로 기본 권고는 PRD를 코드 값으로 갱신.
```

Figma 빌드는 이 리포트의 F2 결정과 무관하게 진행 가능 — 스펙 v2가 코드(현재 화면) 기준으로 작성돼 있어,
F2가 어느 쪽으로 결정되든 값이 바뀐 항목만 스펙 재생성 후 Figma 재빌드하면 된다.
